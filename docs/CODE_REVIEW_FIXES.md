## 更新与启动可靠性复核

日期：2026-10-09。基线：`7c9cc6a`。用户确认安装版优先后台自动更新并重启；便携版不增加自动替换流程。

- Windows 更新使用插件现有 quiet 模式和自动重启能力；macOS 延续已有签名更新与重启。便携下载复用 SHA-256 正确的原名或编号副本，错误同名文件仍不覆盖。原下载命令保持注册与参数兼容，并调用当前清单下载实现。
- 启动配置内容未变化时不重写。启动写盘失败记录现有 persistenceError，显示主窗口和重试入口，调度在写盘恢复前暂停。初次 load_data 使用新增可选 retryPersistence=false 读取已校验数据；旧调用省略参数仍保持原有重试行为。
- 可读取但业务无效的配置不自动重置；初始化错误显示原生对话框，错误中保留配置路径与校验原因。对话框关闭后退出，未创建业务状态时的退出和单实例回调不再直接访问缺失状态。
- Gitee 重跑复用内容相同的已验证清单；替换失败尝试恢复原清单并仍报告工作流失败。如果 Gitee 同时拒绝恢复，会聚合报告两次错误；附件 API 的删除与上传仍存在短暂空窗，不宣称原子替换。
- curl 回退通过标准输入传入配置，query 和 multipart 均带令牌；临时文件仅包含附件，完成或失败后清理。令牌不进入进程命令参数，curl 错误仅记录退出码。
- 版本显示保留完整补丁号；每日调度测试直接覆盖生产 next_recurring 的当天、等时、次日分支，删除仅测试使用的 next_daily。发布校验增加 Cargo.lock 和 UI 回退版本一致性，本地 Store 构建增加 --locked。

验证：项目测试 101 项、官网测试 11 项、Windows Rust 测试 60 项全部通过；前端类型检查与生产构建通过；PowerShell 构建脚本语法检查通过。发布版本校验实测接受一致版本、拒绝 UI 或锁文件不一致；真实 curl 对本机 HTTP 服务的 query、multipart 令牌和附件内容验证通过。Rust 回归使用真实 Windows 文件共享锁验证跳过无变化配置及失败时保留原内容。

范围与限制：保留签名、SHA-256、业务校验、旧 IPC 命令和事件、多语言及现有窗口同步保护；未进行保存协议、锁、模块或自启动重构。未更改应用版本或推送发布标签。本机未实际安装更新、操作系统电源动作或访问 Gitee 上传；macOS、ARM64 运行以及原生启动错误对话框仍需实机验证。检查范围内 UTF-8 无替换字符或常见乱码特征。MSVC 创建导入库提示仍存在，无编译失败。
